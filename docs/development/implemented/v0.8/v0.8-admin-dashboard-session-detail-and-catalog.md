# v0.8 — Admin dashboard session detail, candidate directory, and skills catalog

**Status:** Implemented (documentation revision)  
**Date:** 2026-05-04  

## Summary

This revision tightens the operator experience on the Next.js admin surface and the voice-engine APIs that feed it: assessment rows now derive **duration**, **confidence**, and **max SFIA level** from the same signals as the session detail view (including holistic assessment when per-claim levels are unset). The **call detail modal** shows **transcript** and **holistic-driven summary** content, splits claims into **SME** vs **supervisor** tabs (supervisor view hides skill codes and level ladders), and exposes **SME / supervisor review URLs with copy buttons** in the modal header for authenticated admins only. Operators can **verify, reject, or flag** individual claims with a comment via a dedicated admin API.

New **Candidates** and **Skills library** routes under `/dashboard/candidates` and `/dashboard/skills` replace non-functional sidebar buttons with working pages: candidates are ordered by most recent session, rows expand to list calls, and **call settings** opens a modal for cooldown override and no-restrictions toggles. The skills page lists framework skills with modal-based add/edit for catalog text; **embeddings remain script-managed** and are called out explicitly in the UI.

A companion script **`scripts/load-mock-interview.sh`** (voice-engine module `src.testing.load_mock_interview`) reloads an exported `mock-interview-*.json` into Postgres so the same dashboard views apply to historical mock runs.

## Voice engine

- **`IPersistence`** extended with: `list_candidates_with_sessions`, framework CRUD helpers, `save_admin_claim_flags`, and enriched `list_admin_session_summaries` (holistic JSON + `metadata` for recording duration fallback).
- **`get_report` / admin session report** include `transcript_json`; public expert/supervisor token reads stay compact (no transcript leakage).
- **`save_report`** no longer overwrites an existing `transcript_json` when the UPDATE runs after finalize (transcript is preserved).
- **Mock interview** `finalize()` passes `recording_duration_seconds` from elapsed wall time for dashboard duration when timestamps are missing.
- **Optional `ADMIN_TOKEN`**: when set, gated admin routes require matching `X-Admin-Token` (Next.js BFF forwards the httpOnly `admin_session` cookie as that header).
- **Supervisor review API** accepts `flagged` as a decision alongside `verified` and `rejected`; comments are optional unless the upstream validation requires them for reject flows.

## Web (Next.js)

- **API routes** under `/api/admin/*` forward `X-Admin-Token` for voice-engine auth.
- **`AssessmentReviewModal` / `ClaimsRegisterTable` / `ScoreStrip` / `ModalHeader`** updated for the new layout and behaviours.
- **`map-assessment-report`** centralises snake_case → camelCase mapping for claims (including `sfia_skill_code`, `sfia_level`, `claim_type`, admin fields).

## Scripts

- **`scripts/load-mock-interview.sh`** — interactive picker for `scripts/mock-results/mock-interview-*.json`, then loads into the database configured by `DATABASE_URL`.

## Operational notes

- Set **`ADMIN_TOKEN`** in both the Next.js app and the voice-engine environment so admin-only voice routes and the session report endpoint are protected consistently.
- After changing skill **level text** in the admin UI, re-run the **ingestion** pipeline to refresh pgvector embeddings; the UI states this explicitly.

## Validation

Run `./validate.sh` from a developer machine with `pnpm`, Prisma, and the voice-engine `.venv` installed per `CLAUDE.md`. The cloud agent sandbox used for this change did not include those tools; local CI should be used as the source of truth for green builds.
